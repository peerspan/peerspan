## Purpose

Tracking PR for the complete guided onboarding feature. The owner approved this experience:

1. **Connect this project** from inside the existing agent session.
2. **Invite someone** or **connect my other computer**.
3. Each participant reviews the relevant identity and permissions in their own guided flow.
4. Peerspan completes the intermediate steps and shows actual connection readiness.

## Branch and integration policy

- Integration branch: `codex/guided-session-onboarding`.
- Started from main at `2719d9978ddb86fba003675217fd04922de77a9f` in a separate checkout.
- Small implementation PRs target **this feature branch**, not main.
- This tracking PR is the eventual combined feature PR into main. Keep it unmerged until the implementation, reviews and final acceptance are complete.
- Update this description with each slice's PR, reviewed commit and test evidence.

## Slices

- [ ] **GU-01 — Flow contract:** participant actions, private handoff, exact reviews, resumable state, readiness and independent verification cases.
- [ ] **GU-02 — Owner-local orchestration:** derive the next action and carry exact protocol references automatically.
- [ ] **GU-03 — Existing-session entry point:** connect or resume the current project without replacing the conversation.
- [ ] **GU-04 — Invite a teammate:** guide separate owner, administrator and requester decisions and explicitly review agent access.
- [ ] **GU-05 — Connect my other computer:** approve its exact device and powers without copying the original person key.
- [ ] **GU-06 — Progress and recovery:** resume interrupted work and explain waiting, refusal, expiry and connectivity failures; establish actual readiness.
- [ ] **GU-07 — Installation and guide:** one supported first-use path, with advanced administration outside the normal flow.
- [ ] **GU-08 — Verification:** independent conformance, installed acceptance and a real existing-session exchange on the final feature head.

Full requirements, dependencies and acceptance: [feature plan](https://github.com/peerspan/peerspan/blob/codex/guided-session-onboarding/docs/guided-session-onboarding.md). Owner confirmations are recorded as GU-OWN1 and GU-OWN2 in [the decision log](https://github.com/peerspan/peerspan/blob/codex/guided-session-onboarding/docs/decision-log.md).

## Required boundaries

- Hosts retain local authorization; no required Peerspan service.
- Membership and owner access remain separate.
- Preserve the distinct participant approvals, exact reviewed terms and durable signing/publication order.
- Keep original keys on their original machines and private handoffs out of command arguments, routine logs and model context.
- Owner administration remains separate from credential-scoped agent and peer APIs.
- A prepared config or plugin reload is not a verified incoming-delivery path.
